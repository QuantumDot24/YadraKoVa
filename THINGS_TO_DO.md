Lo que falta del core (no de kernels específicos, sino de la infraestructura base)
1. Pinned host memory (core/host_buffer.h) — pendiente desde que lo mencionamos. Necesario para cuando cargues pesos reales de Qwen3.5 desde disco; sin esto, las transferencias host→device son más lentas de lo necesario. No urge hoy, urge cuando empieces a mover tensores grandes.
2. Un Allocator/helper de transferencia (core/transfer.h o similar) — ahorita cada test hace cudaMemcpy a mano con tamaños calculados manualmente. Sería razonable tener algo como Tensor::to_device(host_ptr) / Tensor::to_host() como métodos de conveniencia, para no repetir ese boilerplate en cada kernel nuevo que pruebes.
3. Multi-stream real en GraphManager — ahorita mismo todo corre implícitamente sobre streams pasados a mano; no hay todavía un mecanismo para que GraphManager asigne automáticamente streams distintos a grafos que quieras correr en paralelo (ej: telemetry en un stream separado del training). Es una extensión pequeña sobre lo que ya existe.
4. Manejo de errores CUDA centralizado — ahorita cada wrapper (Stream, Event, Graph) repite el mismo patrón if (err != cudaSuccess) throw .... Funciona, pero valdría la pena un helper tipo CUDA_CHECK(expr) macro o función inline, para no repetir ese boilerplate en cada archivo nuevo (incluyendo cuando escribas flash_attn.cu, conv1d.cu, adamw.cu).
5. core/dtype_utils.h — conversión bf16↔fp32↔fp16 y (cuando toque) cuantización int8 la estás haciendo a mano en cada test (__float2bfloat16, etc.). Si vas a repetir esto en más tests, tiene sentido centralizarlo.
